# Every entry below is classified by WHERE ITS OUTPUT LANDS, audited
# 2026-09-19 (ticket T-25). The rule, from the pypdf story (ticket T-24):
# a dependency whose output reaches a STORED VALUE, a KEY, or SCRUBBED
# TEXT is pinned exactly; everything else keeps a floor.
#
# Why a floor is not enough for those: a floor does not discriminate.
# `pypdf>=5.1` had already allowed an in-place jump to 6.19.0, and pypdf
# feeds `description`, which is part of the de-duplication key -- so an
# upgrade changing whitespace handling changes the key for every
# previously imported row, silently, with re-imports simply starting to
# create duplicates.
#
# The distinction that decides each line is LOUD versus SILENT. A change
# in something read at request time shows up the next time you look. A
# change in something written into a row is permanent, and nothing
# re-derives it to notice.

# --- pinned: output lands in a stored value or a key -------------------

# Parses and coerces `txn_date` (a `date`) and `amount_cents` (StrictInt)
# on the way in; both are part of the account-scoped dedup key. A change
# in coercion changes what is stored and therefore what dedups.
#
# I first flagged this as borderline on the grounds that a coercion
# change would "most likely fail loudly" as a validation error. That
# reasoning was wrong, and the correction is worth keeping because it is
# the whole point of the loud/silent test: MOST LIKELY LOUD IS NOT
# GUARANTEED LOUD, and the failures that matter are the ones that are
# not. A stricter parse rejects and shouts. A more LENIENT parse accepts
# what it used to reject -- or reads an ambiguous date differently -- and
# returns 200 having written a different key. That is the silent case,
# and a floor permits exactly the upgrade that produces it.
#
# Not hypothetical: 2.13.5 ALREADY does this. A datetime string is
# accepted on a `date` field at exactly 00:00:00, keeping the calendar
# date and discarding the offset (ticket T-22). The key-family fields
# are now guarded by `KeyDate` in api/models.py, so the leniency is fenced
# off at our boundary rather than depended upon to stay absent -- but the
# lesson stands: the coercion this pin protects against is one this
# version performs today, on a value nobody probed.
pydantic==2.13.5

# Parses the multipart upload whose `filename` and `content_hash` are
# INSERTed into ticket_attachments. A change in how it decodes a filename
# changes a stored value, and content_hash is computed from what it
# hands us.
python-multipart==0.0.32

# Extracts statement text, which becomes `description` -- part of the

# Upgrade deliberately, and re-run api/tests/test_scrubber_determinism.py
# plus a re-import when you do.
pypdf==6.19.0
